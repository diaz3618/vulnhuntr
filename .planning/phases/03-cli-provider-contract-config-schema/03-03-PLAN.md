<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| args.llm → initialize_llm | User-controlled string from CLI/config selects which provider branch runs |
| probe() result → SystemExit decision | CapabilityResult.ok=False triggers process exit |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | Tampering | `initialize_llm` provider string routing | mitigate | Exact string matching (`llm_arg == "claude-code"`) prevents partial-match injection. `llm_arg = llm_arg.lower()` is already applied before branching. Unknown strings reach the `ValueError` branch cleanly. |
| T-03-10 | Elevation of Privilege | Probe called on FallbackLLM wrapper | mitigate | `hasattr(llm, "probe")` check on the UNWRAPPED `llm` instance before `wrap_with_fallbacks()` is called. Comment in code explains why (Pitfall 2). Test `test_probe_called_before_wrap_with_fallbacks` verifies this at runtime. |
| T-03-11 | Denial of Service | probe() hanging on wrapped instance | accept | Phase 3 does not instantiate real CLI providers — stubs raise NotImplementedError. The real probe timeout protection (stdin=DEVNULL, 10s timeout in the --version call) is enforced in Plan 01's `_run_subprocess`. Low risk at this stage. |
</threat_model>
