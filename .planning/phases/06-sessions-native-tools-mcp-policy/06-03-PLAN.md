  <files>vulnhuntr/cli/runner.py</files>
  <action>
The correct insertion point is after `_analyze_files()` returns (Stage 3 complete),
not inside the per-file loop. Writing once after the first successful analysis is
sufficient because `session_id` is set on the LLM object by the first `send_message()`
call and does not change for the remainder of the scan.

However, reading the code more carefully: `_analyze_files()` is the stage that does the
actual LLM calls. The `llm` object will have `session_id` populated after the first call
inside `_analyze_files()`. So we write metadata to the checkpoint right after
`_analyze_files()` returns (before finalize).

Find the `all_findings, analysis_success = _analyze_files(...)` line in `run_analysis()`.
After that line, add the following block:

```python
# Persist session metadata to checkpoint when using a session-aware CLI provider.
# D-07: write after first successful call when session_mode != "stateless".
cli_policy = getattr(config, "cli", None)
session_mode = getattr(cli_policy, "session_mode", "stateless") if cli_policy else "stateless"
if session_mode != "stateless" and hasattr(llm, "get_session_metadata"):
    metadata = llm.get_session_metadata()
    if metadata and checkpoint._data is not None:
        checkpoint._data.session_metadata = metadata
        checkpoint.save()
```

This code:
- Only runs when a non-stateless session_mode is configured
- Only runs when the LLM has a `get_session_metadata` method (i.e., it's a CLI provider)
- Only writes when the provider actually captured a session_id (get_session_metadata returns non-None)
- Only writes when a checkpoint is active (checkpoint._data is not None)
- Calls `checkpoint.save()` immediately so the metadata survives if the scan fails afterward

The `config` variable is available in `run_analysis()` — it is passed in and used
for `_init_providers()`. The `llm` variable is the final LLM instance (the one
reinitialized with system_prompt).
